# Image optimization

[Documentation index](README.md)

All future migrations apply a fidelity-first, smaller-only WebP policy to localized JPEG/PNG media: lossless cwebp with exact transparent pixels, preserving metadata. This avoids adding lossy compression artifacts to the source. Image elements, responsive candidates, CSS backgrounds and embedded featured images use the localized path. SVG, GIF, WebP, AVIF and animated PNG remain in their original formats. If cwebp is missing, fails, or produces a larger file, the original works normally. Install cwebp on PATH or set CWEBP_BIN; conversion is optional and requires no AI or service credentials.

Export metadata supplies the local featured image to the native SSG. Still-image featured assets go through its image processor; its generated images directory is carried into the final export. Unsupported/animated featured assets remain as localized originals instead of being flattened. Authors and featured media depend on public REST `_embed` responses; private/unavailable values are not invented.

`metrics.imageOptimization` reports optimized media, byte savings for referenced media, and encoder fallbacks. Each media record retains originalBytes and the conversion status. Resume upgrades old localized media and checkpoints the rewritten references. Old source files may remain in a resumed project for recovery, so referenced-byte savings are not a promise of identical ZIP savings.

RSS is generated by native SSG, combined across bounded compilation batches and rewritten to the final source-preserving routes. It contains the latest 20 public posts with native excerpts/dates by default; feed_limit: 0 retains all public posts. Excluded/noindex posts stay out; GitHub Pages base paths are supported. This is a new local RSS export, not an import of arbitrary source feed extensions. Captured archive and pagination pages retain their design. Supplemental native-card collection/taxonomy listings regenerate from the route manifest and current metadata; recognized source archive bindings also regenerate; ambiguous layouts automatically receive native SSG listings. See `ssg-feature-checklist.md`.
